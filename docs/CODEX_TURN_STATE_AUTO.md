# CallAI：klno.9 自然积累与自动接管

本功能选择性移植 `KlN-4096/sub2api` 的 `v0.2.5-klno.9`，源提交 `2b6600c0360b9eefb60e91c4282b83ec385fadf1`，保留 LGPL-3.0 许可证及来源说明。形态解析文件直接移植；候选选择、会话判定和形态测试沿用其算法并适配 CallAI 的存储、安全和调度边界。

## 使用方式

系统设置现有 Codex 指纹增强旁新增 **Codex Turn-State 自动接管**，通过既有 `GET/PATCH /api/v1/admin/settings/openai-oauth-runtime` 的 `openai_oauth_turn_state_auto_enabled` 管理。默认关闭，未配置字段的旧版本保持关闭；开启覆盖全部 OpenAI OAuth 账号及后续新增账号。独立于指纹增强和短时换代理，不更改其他开关。没有功能环境变量、手填状态、采集代理或主动探测任务。

自动接管只支持 HTTP/SSE，WS 以及 WS 入口的 HTTP 桥维持原转发及原有长度诊断。设置关闭、候选缺失/过期、数据读取失败时原样转发；候选被上游拒绝后标记失败，但**不更改账号状态、schedulable、额度或重试预算**。关掉功能停止新的注入与候选维护，轻量自然形态观测仍保留。候选清空/耗尽不要求停站处理。

## 形态、隔离与保存

- 按 klno.9 解析 Fernet 形状的公开信封，读取时间戳和密文块数，不解密、不验签。10/12 块为基线，11/13 块为常见非基线；常见字符长度分别为292/332和312/356。解析失败按292/332字符兜底，其余形态进入需要接管的判断。
- 这些都是经验形态规则，不是模型质量结论，也不保证注入会减少限流。候选只来自真实上游响应，不从客户端请求直接建立池。
- 候选按上游凭证归属及实际出站模型隔离；影子账号使用母账号池。会话是否需要接管另按用户所持 API Key、会话、凭证归属和模型隔离，无会话ID仍按API Key隔离。没有API Key的内部上下文使用请求级隔离。
- 每模型最多3条，每账号最多16个模型；优先移除过期条目，再按最新观察顺序保留模型。默认寿命60分钟，从公开签发时间起算，无法解析时用真实观测时间兜底。
- 只给已标记的会话使用可用候选，注入后收到较长状态不作候选失效依据。`invalid_encrypted_content` 会标记本次实际注入的候选失败；日志标为歧义拒绝信号，因为这个错误也可能与请求中的其他加密内容有关。
- 保留有期限的拒绝摘要，防止失败候选被挤出池后再次被观察到而复活。拒绝记录有容量上限，达到上限时暂停补充，已有可用候选仍可使用；不恢复失效值来腾空间。
- 会话判断是进程内有界缓存（8192项、1小时），重启或切换进程会重新观察会话；候选和拒绝记录跨进程共享。多实例并发更新由 PostgreSQL 账号行锁保护，不依赖进程内锁保证一致性。
- 候选池用既有 `SecretEncryptor` / AES-GCM 加密写账号 extra。开启前校验已配置有效加密密钥；不引入新的业务表或迁移。更换既有加密密钥会影响已有加密数据，不能随意轮换。
- 账号普通编辑在同一行锁下保留最新受管字段；客户端不能通过创建/导入/编辑注入候选。上游身份变化使旧池无效，正常令牌刷新不更改身份归属。无法确定上游账号/工作区身份、只有设备种子时跳过接管并记录原因，避免重新授权后串用旧票。账号列表与导出均不包含完整状态或候选密文。
- 数据操作使用短超时（每次250ms）；不可用时不注入、写失败记录错误，不阻断正常转发。池维护不触发调度桶重建。

账号列表的额度区域展示最近自然形态、模型、时间及每模型可用候选和到期时间，区分仅观测、等待候选、可接管、过期、被拒绝。影子行显示母账号归属；完整池信息在母账号行。没有新增页面或上游轮询。

## 独立可观测性

独立 JSON 日志写入现有持久化数据目录的 `logs/codex-turn-state.log`；容器默认路径 `/app/data/logs/codex-turn-state.log`。不受应用 warn/info 级别影响，不进入 Ops 数据库日志 sink，不采样。

- 单文件100MB、最多10个归档、最多7天、压缩归档。超过容量会先淘汰旧文件，因此高流量时实际历史可能短于7天。
- 每个尝试记录开关状态、跳过原因、候选注入、形态观测/新增、拒绝与耗尽、存储失败、上游状态、首个可见输出、读取结束及错误分类。
- `process_ref`、`request_ref`、账号/会话摘要用于关联，摘要使用进程随机密钥；只能在同一进程内比较，与现有长度诊断使用同一摘要机制。`attempt` 是出站尝试序号，不能当成用户请求次数。
- `original_length` / `sent_length` / 响应 `length` 区分原始、实际发送及返回状态。长度、块数和候选年龄可记录，完整状态、状态前缀、正文、OAuth凭据、代理密码不记录。
- 响应流只随业务读取被动观察，不提前消费，不改变返回字节或原始错误。单事件及非SSE观测前缀有64KiB上限，截断明确记录；截断后缺少终止事件不等于上游失败，EOF也不能证明用户收到完整结果。
- 日志写入失败累计 `log_write_failures`，并以限频应用错误日志 `codex_turn_state_log_write_failed` 提示；只限频这条重复故障提示，不采样决策记录，也不因磁盘故障使转发失败。

现有 `codex_state_diagnostic` 与 `backend/scripts/codex_state_lengths.py` 保留，HTTP状态码与state长度分开统计。第一次上线应核对独立日志写权限、轮转、实际出站头、候选失效、首字延迟与正常请求容量。
