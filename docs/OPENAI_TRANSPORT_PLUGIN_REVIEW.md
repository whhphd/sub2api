# 打票插件评估留档

评估日期：2026-09-19（含当日晚间新版复评）。结论：**新版增强了诊断展示，但仍不适合替换 CallAI 猎手。** 生产未安装或启用插件，现有猎手配置保留。

## 新版 v0.2.7.1 复评

用户提供 `v0.2.7.1-linux-amd64.s2plugin` 和 `v0.2.7.1-linux-arm64.s2plugin`。两包内部清单均为 **0.2.7**，amd64 运行时 GetInfo 也报告 0.2.7；宿主要求仍为 `>=0.2.7 <0.3.0`。两包文件摘要及原版内置发布者公钥的 Ed25519 签名均通过。OVH 为 x86_64，本次只动态执行 amd64，arm64 仅做包完整性与签名检查；两者 UI 文件摘要完全一致。

新增“打票日志与诊断”：采票成功/失败/注入缺失计数、问题账号、连续失败、最近错误和最近采票事件；可每 15 秒刷新。UI 区分身份解析、代理、请求、上游和无效票据错误。静态分析显示事件列表限制为 400 条并合并连续重复事件，错误文字限制约 300 字节；这不等同于本地独立持久化决策日志，也未证明错误文字经过凭据脱敏。

| 重点复测 | 新版实测 |
|---|---|
| JSON 注入 | 正常，将客户端 356 替换为模拟 KV 中的 292；出站值与候选完全相同 |
| zstd 注入 | **问题仍在**：相同账号、模型和候选，压缩后仍发送客户端 356；请求本身可正常解压转发 |
| 新增“注入缺失”统计 | 普通 JSON 缺票能计数，但两次 zstd 漏注入未增加计数，存在观测盲区 |
| HTTP 400 候选拒绝 | `invalid_encrypted_content` 后下一请求仍发送同一候选；模拟 KV 未收到删除或更新 |
| SSE 候选拒绝 | HTTP 200 SSE error 中的同类错误后，也继续发送同一候选 |
| 自然响应采集 | 本次自然基线形态响应未写入 KV，下一请求仍发送客户端原状态 |
| 账号/模型隔离与关闭 | 其他账号/模型不使用此候选；关闭后恢复客户端原状态 |
| 目标模型 | 二进制门控列表仍固定为 Sol、Astra；UI 无模型配置入口 |
| 代理配置 | 仍为一个专用代理 URL，支持 `{random}`；留空时使用账号可用代理。没有本地现用的多个专用代理选择与分国家统计入口 |

这次核心实验使用可真正读写、删除和列出键的内存 KV，避免模拟宿主不处理删除掩盖候选失效逻辑。无外网、只读容器、非 root、伪凭据和本地回显上游；合成状态仅用于验证选择和发送字节，不验证真实上游是否接受。后台探测账号目录为空，未主动向 AI 服务发请求。没有对新版真实命中率、配额跳过、所有重试和多实例场景作保证。

**仍建议保留 CallAI 猎手。** 最近一次运行配置中，GPT-5.5 已由用户加入免暂停名单，因此插件固定模型范围不再单独作为当下的替换阻碍；关键阻碍仍是 zstd、拒绝后复用，以及多专用代理/预算/模型级暂停/可观测性差异。新增诊断页面值得借鉴，但本轮不修改业务功能。

## 关键结果

| 检查项 | 本次插件表现 |
|---|---|
| 普通 JSON 请求注入 | 模拟 KV 有对应候选时，将原 356 字符状态替换为 292 |
| zstd 请求注入 | 相同账号、模型和候选，改为 zstd 请求体后仍发送原 356，未注入 |
| 候选拒绝 | 模拟 HTTP 400 `invalid_encrypted_content` 后，下一请求仍使用同一候选 |
| 账号和模型隔离 | 本次隔离测试通过，其他账号或模型不复用该候选 |
| 模型范围 | 二进制静态列表为 `gpt-6-astra`、`gpt-5.6-sol`，UI 无模型列表配置 |
| 自然采集 | 本次模拟自然基线形态响应未入池，后续请求未复用 |

zstd 问题影响的是**候选注入，不是请求转发**。CallAI 在压缩前绑定模型信息，插件的模型提取路径直接解析 JSON，因此与当前指纹增强的 zstd 出站请求不兼容。

插件的独立部署、简洁票据总览及 `{random}` 代理模板值得借鉴。但当前未确认它能满足我们的额度耗尽避探测、小时预算、按模型暂停、Terra 豁免和完整决策日志需求。
