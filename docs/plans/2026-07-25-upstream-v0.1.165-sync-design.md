# Upstream v0.1.165 Sync Design

## Goal

Merge upstream sub2api v0.1.165 into the CallAI fork, preserve the OpenAI OAuth
no-op tool-call injection and five-consecutive-429 scheduling policy, validate
the combined behavior, then push, build, and deploy the merged release.

## Merge Strategy

Create a pre-sync backup branch and merge `upstream/main` into `main` without
rewriting published history. The merge preview is conflict-free, but the eight
overlapping OpenAI gateway files require semantic review. Any manual fixes are
split into commits touching no more than three files.

The merged tree must retain both account extra keys, HTTP and WebSocket no-op
injection, the Redis-backed account streak, and a threshold of five. Images,
Embeddings, and Alpha Search must retain their original 429 behavior.

## Verification

Run the full backend test suite, focused injection and 429 tests, relevant
frontend account-modal tests, frontend lint/type checks, and a production
frontend build. Review the upstream OpenAI routing changes against the custom
paths before pushing the fork.

## Database And Deployment

Upstream migrations 187 through 190 add usage session IDs, allow the Live
request type, add the group Live flag, and create an email-alias lookup index.
Back up PostgreSQL and the compose file before deployment. Build a commit-tagged
image on `sub2api-new`, verify that the runtime includes `curl`, and recreate
only the `sub2api` service so PostgreSQL and Redis keep running.

The schema changes are additive or widening and remain compatible with the
previous application image. If application validation fails, restore the prior
compose image immediately; retain the database dump for disaster recovery
rather than restoring it during a normal application rollback.

## Production Checks

Require a healthy container, successful loopback, direct-domain, and
Cloudflare-domain health checks, completed migrations, no startup panic or
Redis/database errors, and successful live API traffic before completion.
