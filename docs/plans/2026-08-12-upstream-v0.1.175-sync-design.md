fork's OpenAI OAuth runtime policy and overload handling, validate the affected

## Merge Strategy

predicted conflicts in two bounded groups:

1. Handler scheduling and lifecycle logging: `failover_loop.go`,
   `openai_chat_completions.go`, and `openai_gateway_handler.go`.
2. Responses stream processing: `openai_gateway_passthrough.go` and

Preserve the fork's global OpenAI OAuth settings, configurable 429 behavior,
safe pre-output overload retries, and overload lifecycle diagnostics. Adopt
upstream's Codex fingerprint convergence, TTFT corrections, deterministic error
classification, response-model billing safeguards, and related fixes.

full handler suite and the broadest practical service suite. Build the Docker
image from the merged commit with the repository Dockerfile, verify `curl` is
present, replace only the `sub2api` container, and confirm health plus production
overload logs. No database migration is required by this upstream update.
