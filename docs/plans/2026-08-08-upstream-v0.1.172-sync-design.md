# Upstream v0.1.172 Sync Design

## Goal

Merge `upstream/main` at v0.1.172 into the CallAI fork, preserve all local OpenAI OAuth experiments, validate the combined count-token behavior, and deploy the tested image to production.

## Merge Strategy

- Merge `upstream/main`, not only the release tag, so the fork includes the post-release VERSION synchronization commit.
- Keep the fork's isolated `/v1/responses/input_tokens` path. OAuth 401, 403, and 404 responses must fall back to one local estimate without retrying, switching accounts, or mutating account health.
- Keep the upstream `/v1/messages/count_tokens` HTML 403 handling. It covers the Anthropic-compatible bridge and prevents proxy-generated HTML errors from cooling OAuth accounts.
- Do not consolidate the two handlers during this sync. They serve different public endpoints and have different request contracts.

## Validation

- Run the direct Responses input-token fallback tests and the upstream Anthropic-compatible HTML 403 test.
- Verify no retry, account switch, temporary unscheduling, or account error mutation occurs on either convenience endpoint.
- Regress the fork's no-op tool-call injection, configurable OAuth 429 threshold, new-account defaults, and request-scoped capacity handling.
- Run affected backend packages, targeted frontend account/settings/usage tests, and the production frontend build.
- Treat unrelated pre-existing flaky tests separately, but do not ignore failures in changed or fork-owned paths.

## Database Changes

- Migration 194 adds nullable `upstream_response_model` and `upstream_model_mismatch` columns to `usage_logs`.
- Migration 195 creates a partial index with `CREATE INDEX CONCURRENTLY`.
- Before deployment, capture a schema-only backup of the affected table and migration metadata. Do not create another full database dump solely for these additive upstream migrations.
- The old application image remains compatible with the added nullable columns and index, so application rollback does not require destructive schema rollback.

## Deployment And Rollback

- Push the tested merge commit to the fork before building production.
- Build on the production server with a temporary 4 GB Node heap override because the committed 1.5 GB build limit is insufficient for the current frontend. Do not change runtime memory settings.
- Confirm the image version and bundled `curl`, back up the compose file, and recreate only the application container.
- Verify migration records, columns, index validity, container health, direct and Cloudflare health endpoints, homepage/auth guards, restart count, and recent application/Nginx errors.
- If startup, migration, or health verification fails, restore the previous compose image tag and recreate only the application container.
